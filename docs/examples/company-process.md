# 公司配置测试环境流程说明（填写后放到私有目录）

业务流程：保存配置并提交工单 → 公司审批人审批 → 公司系统自动发布 → 查询发布结果并核验测试环境。
Agent Platform 不调用审批通过或主动发布工具。

请用公司术语补充以下内容；不填写凭据或真实秘密值：

- `target.environment=test` 对应公司的哪个环境参数？
- `target.resourceRef=app/test-namespace` 如何映射到 app、namespace、集群等参数？
- 保存与提交工单是同一个原子工具，还是两个独立工具？
- 保存如何原子检查资源版本、条目版本或不存在条件？请求有效期字段是什么？
- 保存/提单的幂等请求标识字段和查询原结果的方式；查询结果是否保留原提交时间？
- 工单如何绑定确切的变更 ID、变更版本和目标环境？
- 公司工单状态（待审批/通过/拒绝/撤回/失效）的实际枚举含义。
- 自动发布状态（等待/发布中/已发布/失败）的实际枚举含义。
- 哪个查询读取保存草稿，哪个查询读取测试环境已发布的版本和值？
- 字段类型、数字/布尔的表示方式、非敏感试点 key 的限制。
- 是否允许每个配置动作单独提单？首版按动作提单，合并多项配置的单工单未实现。

这些说明用于模型建议映射，不是运行时权限。缺失契约应产生待确认问题，不能推断成成功。
